# M1.0-A — GLOBAL SCHEMA CONVENTIONS

**Status:** FROZEN

* **A01 (Internal PK):** Tất cả 15 bảng dùng `id UUID PRIMARY KEY`.


* **A02 (External IDs):** `TEXT` hoặc `VARCHAR`, cấm dùng kiểu số.


* **A03 (Datetime):** `TIMESTAMPTZ` (UTC only). Mặc định `DEFAULT now()`. Bảng append-only / history chỉ có `created_at`. Bảng mutable mới có thêm `updated_at`.


* **A04 (Nullable):** Mặc định `NOT NULL`. `NULL` chỉ dùng khi mang nghĩa chưa có dữ liệu / không xác định. Không dùng chuỗi rỗng `''` thay thế `NULL`.


* **A05 (Status / Enums):** `VARCHAR(...)` kèm `CHECK (col IN (...))`. Cấm dùng PostgreSQL Native ENUM (`CREATE TYPE ... AS ENUM`).


* **A06 (Workflow vs. Decision):** Tách bạch kết luận máy (`recommendation`: `MATCH`, `NO_MATCH`, `MANUAL_VERIFY`) khỏi trạng thái quyết định của con người (`status`: `CANDIDATE`, `APPROVED`, `REJECTED`, `REVOKED`).


* **A07 (Soft-delete):** Không dùng cờ chung `deleted_at`/`is_deleted`. Dùng cờ nghiệp vụ (`is_active`, `status = 'REVOKED'`).


* **A08 (Audit / History Mutation):** Nghiêm cấm `UPDATE` hoặc `DELETE` trên các bảng event, history, evidence, review.


* **A09 (Optimistic Locking):** Chỉ đặt `version INTEGER NOT NULL DEFAULT 1` (`CHECK (version >= 1)`) trên các **Mutable Aggregate Roots** (`lecturers`, `publications`, `scopus_imports`, `lecturer_scopus_identities`, `users`).


* **A10 (FK Default):** Mặc định `ON DELETE RESTRICT` (hoặc `NO ACTION`) cho tất cả các quan hệ tham chiếu dữ liệu và provenance.


* **A11 (FK Cascade):** Chỉ dùng `ON DELETE CASCADE` cho quan hệ thành phần phụ thuộc thuần túy (`publication_authors.publication_id -> publications(id)`).


* **A12 (JSONB):** Chỉ dùng lưu payload thô, metadata bằng chứng, snapshot trạng thái audit và danh sách lỗi validation. Phải có CHECK `jsonb_typeof(...)` tương ứng. Không dùng JSONB thay thế quan hệ thực thể quan trọng.


* **A13 (Canonical EID):** `publications.eid` bắt buộc `UNIQUE`.


* **A14 (Raw EID):** `raw_scopus_records.eid` tuyệt đối **KHÔNG UNIQUE** toàn hệ thống.


* **A15 (DB Invariants):** Enforce mọi quy tắc toàn vẹn bằng DB Constraint (CHECK, UNIQUE, Partial Index).


* **A16 & A17 (Naming Convention):**
* Tables: `snake_case`, số nhiều.


* Foreign Keys: `<referenced_entity>_id`.


* Template Alembic MetaData:
* `pk`: `pk_%(table_name)s`

* `fk`: `fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s`

* `uq`: `uq_%(table_name)s_%(column_0_name)s`

* `ck`: `ck_%(table_name)s_%(constraint_name)s`

* `ix`: `ix_%(table_name)s_%(column_0_label)s`



* Các composite constraints / partial indexes phải đặt tên tường minh, không dựa vào sinh tự động.

## M1C-01 — Lecturer Snapshot / Known Publication Integrity

**Decision:** Composite Foreign Key enforcement.

Parent candidate key:

```sql
ALTER TABLE lecturer_source_snapshots
ADD CONSTRAINT uq_lecturer_source_snapshots_id_lecturer
UNIQUE (id, lecturer_id);
```

Child integrity constraint:

```sql
ALTER TABLE lecturer_known_publications
ADD CONSTRAINT fk_lecturer_known_publications_snapshot_lecturer
FOREIGN KEY (snapshot_id, lecturer_id)
REFERENCES lecturer_source_snapshots(id, lecturer_id)
ON DELETE RESTRICT;
```

Invariant:

```text
lecturer_known_publications.lecturer_id
    ==
referenced lecturer_source_snapshots.lecturer_id
```

PostgreSQL indexing rule:

- A FOREIGN KEY does **not** create a child-side index automatically.
- `ix_lecturer_known_publications_lecturer_id` remains an independent query-path index for matching workloads.
- The parent `UNIQUE (id, lecturer_id)` is intentionally retained to support the referenced composite candidate key.

## M1C-04 — Deterministic SHA-256 Contract

All persisted SHA-256 text values:

```text
lowercase hexadecimal
exactly 64 characters
regex: ^[0-9a-f]{64}$
```

### `scopus_imports.file_sha256`

Input is the exact raw uploaded byte stream:

```python
sha256(file_bytes).hexdigest()
```

No decoding, newline conversion, CSV parsing, trimming, or other preprocessing occurs before hashing.

### `lecturer_source_snapshots.snapshot_hash`

Input is the crawler payload only, serialized as canonical JSON:

```python
json.dumps(
    payload,
    sort_keys=True,
    separators=(",", ":"),
    ensure_ascii=False,
    allow_nan=False,
).encode("utf-8")
```

Excluded from the payload hash:

```text
fetched_at
parser_version
created_at
database-generated identifiers
execution metadata
```

Array order must itself be deterministic. Arrays whose business semantics are unordered must be normalized before hashing.

### `raw_scopus_records.row_hash`

Input is exactly the 22 raw Scopus CSV values in frozen canonical header order.

Canonical representation is one JSON array; delimiter-concatenation alternatives are forbidden.

```python
serialized = json.dumps(
    values,
    separators=(",", ":"),
    ensure_ascii=False,
    allow_nan=False,
).encode("utf-8")

row_hash = sha256(serialized).hexdigest()
```

### `identity_evidence.evidence_fingerprint`

Fingerprint payload:

```json
{
  "identity_id": "...",
  "evidence_type": "...",
  "features": {},
  "source_refs": []
}
```

Excluded:

```text
identity_evidence.id
created_at
updated_at
random execution/event identifiers
```

`identity_id` is intentionally included to scope deduplication to the parent identity.

When `source_refs` is semantically unordered, its ordering must be normalized before hashing.

Canonical serialization:

```python
json.dumps(
    fingerprint_payload,
    sort_keys=True,
    separators=(",", ":"),
    ensure_ascii=False,
    allow_nan=False,
).encode("utf-8")
```

# M1.0-FC-01 — CHECK CONSTRAINT NAMES

**Status:** RESOLVED / FROZEN

## Rule

M1.0-A naming convention:

```text
ck_%(table_name)s_%(constraint_name)s
```

For SQLAlchemy `CheckConstraint(..., name=...)`, pass the **semantic suffix** shown below.
The resulting physical PostgreSQL constraint name is the frozen `ck_<table>_<suffix>` name.

Example:

```python
CheckConstraint("version >= 1", name="version")
```

renders:

```text
ck_lecturers_version
```

Do **not** pass the already-expanded `ck_...` name as `name=` when the naming convention will expand it again.
