# Gate E.1 — Identity, evidence and governance gaps

2026-10-29. Findings below describe code behavior. They do not assert that a particular live lecturer, source claim or reviewer decision is wrong. R-01…R-18 classifications are in `REQUIREMENT_IMPLEMENTATION_MATRIX.csv`; all existing repository tests cited here are inspected / NOT_EXECUTED.

## Essential invariants versus research vocabulary

The application need not literally adopt T1–T6 as enum names or numeric weights. It must retain observations sufficient to distinguish target-slot publisher ORCID, registry DOI membership, Scopus-profile ORCID, raw source ORCID and aggregator entities; supporting and contrary signals must coexist. A registry not listing a DOI is incomplete evidence, not proof of a different person. A same-name coauthor can share a DOI; no tier should silently create an approved identity.

The corrected tiers in `docs/qa/gate_d4/errata/EVIDENCE_ERRATA_D4_20261029.md` are: T1 target-slot publisher ORCID + registry DOI claim; T2 publisher ORCID without registry support or shifted position; T3 registry + full name; T4 registry + initials; T5 name + affiliation; T6 name. T1 verifies a research author-slot chain, not a human decision or all publications of an ID. COAUTHOR_CLAIM is not target identity support. The 13 cases with conflict indicators and the one CONFLICTING_EVIDENCE research classification are separate measures.

Literal tiers, ranking thresholds, hard-versus-soft DOI conflict policy, publication exclusions and review permissions are owner design decisions. Lossless provenance, no arbitrary collision selection, no automatic acceptance and explicit evidence limitations are integrity requirements.

## Evidence channels that already work

Affiliation alignment preserves full author arrays and multiple affiliation strings/organization entries (`backend/app/services/author_affiliation.py:194-239`, `273-344`), with reasons distinguishing no list, count/name mismatch and identifier conflict. Affiliation importer checks EID/Scopus ID/order/DOI against the canonical slot and withholds trusted links if another source reports ID_CONFLICT/ID_AMBIGUOUS (`backend/app/services/affiliation_import.py:150-178`, `248-319`). These protections should be reused, not described as entirely missing.

ORCID bridge here reads registry **external identifiers**, not DOI works (`backend/app/services/affiliation_online_fetch.py:229-258`, `backend/app/services/affiliation_sources.py:223-228`, `303-319`). It is a different proof from T1. No active lecturer matcher consumes publisher email, ORCID works, profile affiliation, coauthor confirmation or literal evidence weights; `matching/rules/*` and scorer scaffolds are not counted as implementations. Email in the master importer only resolves lecturer records.
