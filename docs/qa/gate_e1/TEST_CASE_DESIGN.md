2026-10-29. These are proposed tests, not implemented fixtures or reported passes. ## Fixture conventions

Use generated lecturer UUIDs L-A/L-B; source profiles `https://example.invalid/lecturer/a` and `/b`; synthetic Scopus IDs S-A=`11111111111`, S-B=`22222222222`, S-C=`33333333333`; EIDs such as `2-s2.0-999000001`; DOI strings `10.99999/gate-e1-a` and `10.99999/gate-e1-b`; and synthetic names/email addresses at `example.invalid`. ORCID-format samples are syntax tokens only, never fetched. Do not copy real names, addresses, phone/DOB, research DOI rows or raw ORCID records into committed fixtures. Labels AMB/UNA/FINDING only identify the research pattern that inspired a test.

Three test levels: pure functions with no application bootstrap; isolated disposable DB integration in a separately authorized implementation phase; API/UI contract tests with synthetic responses. A dedicated pure-test runner must avoid the current root conftest rather than silently connecting to the configured environment.
